# 小二哈新增动作

本批使用 `apps/pet-device/assets/sprites/husky-six-actions.png`，按 3 行 8 列提取 6 组动画，每组 4 帧。各组使用统一裁切范围，清除边缘的邻帧残片，缩放为 140 × 132 像素后压缩并嵌入设备。

| 动作 | 什么时候播放 |
| --- | --- |
| 玩球 | 家长创建商品并选择“玩球”，设备购买成功后播放，计为陪伴 |
| 洗澡 | 家长创建商品并选择“洗澡”，购买成功后播放 |
| 吃零食 | 家长创建商品并选择“吃零食”，购买成功后播放；零食不替代正餐 |
| 试穿衣服 | 家长创建商品并选择“试穿衣服”，购买成功后播放一次，随后恢复原来的样子 |
| 任务庆祝 | 设备上完成自动奖励任务，或检测到家长审批通过且宠物清醒时播放 |
| 伸懒腰 | 宠物清醒且无其他需求时，正常待机累计约 45～90 秒偶尔播放一次 |

待机手势在产生饥饿、口渴、困倦、想陪伴或睡眠需求时中断；屏幕熄灭、打开菜单、设置及任务界面时不播放。已有 Water 和 Food 的商品、价格和行为不变；四种新商品由家长自行命名、定价并添加，仍受全家最多 10 个商品限制。

## 上线与预览

1. 在 Supabase SQL Editor 执行 `supabase/migrations/20261119_six_pet_animations.sql`，增加商品动作约束，不删除数据。
2. 编译并烧录 `apps/pet-device` 固件。旧版服务端仍可与新版固件配合使用已有商品。
3. 提交推送并部署最新 `apps/parent-h5` 后，在“宝贝与小宠 → 小宠商店 → 添加商品”选择新动作；设备联网同步目录后，点击小狗即可看到商品。

必须先升级设备，再在家长端创建新动作商品：旧固件不认识新动作，可能使商店目录不可用。家长端部署前，固件中的任务庆祝和待机伸懒腰已经可以使用。

浏览器打开 `apps/pet-device/preview/index.html`，可点击“预览新商品动作”“预览任务庆祝”和“预览伸懒腰”；这里使用模拟金币和商品，不请求真实接口。

## 素材处理与验证

- `python3 apps/pet-device/tools/extract_six_actions.py` 从原图生成未压缩帧；`compress_tinypng.py` 读取本机忽略的密钥，只有压缩后更小时才替换；最后通过 `embed_frames.py --report apps/pet-device/assets/frame-storage.json` 重新生成固件资源。
- 这 24 帧从 509,722 字节压至 213,893 字节。所有 64 帧合计 605,510 字节；固件实际大小和剩余空间以构建输出为准。
- LVGL 离线渲染检查验证 64 帧的每个 RGB565 像素及菜单缩放重绘；数据库测试 `supabase/tests/six_pet_animations.sql` 仅在隔离测试库运行并回滚。
