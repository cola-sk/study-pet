# 家长端 H5 整体技术方案（Next.js 14 + Ant Design Mobile + PWA 离线安装）

> 本方案基于 `docs/产品方案.md`，专为“学习任务养成宠物桌面设备”项目设计，定位为**基于 Next.js 14 与 Ant Design Mobile、原生深度适配 Vercel、具备原生 App 质感、支持浏览器直接“离线安装到手机主屏幕”的渐进式 Web 应用（PWA）**。

---

## 一、方案定位与设计目标

### 1.1 核心价值
1. **Vercel 原生一等公民支持，零分发门槛**：基于 Next.js 技术栈，无需配置繁琐路由，Vercel 自动识别部署；全平台现代浏览器（iOS Safari、Android Chrome 等）秒速打开。
2. **全兼容环境变量映射（无需修改 Vercel 变量名）**：在 `next.config.mjs` 中内置全称映射层，无论在 Vercel 命名为 `SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_URL` 还是 `VITE_SUPABASE_URL`，均自动映射识别，彻底规避客户端变量注入失败问题。
3. **支持“离线安装到手机桌面”（PWA & A2HS）**：
   - 用户在手机浏览器打开即可一键“添加到主屏幕”，生成独立图标。
   - 启动时拥有原生全屏（Standalone）无地址栏、无底部回退栏的沉浸式体验。
   - 具备离线秒开能力（自定义 Service Worker 离线缓存），断网时仍可即时查看今日任务、家庭数据与金币流水。
4. **闭环高效操作**：专为家长打造的“多设备/多孩子规则制定与审核工作台”：
   - 支持绑定多台微雪 ESP32 硬件设备，给每台设备分配归属孩子（如“大宝天天”、“二宝果果”）；
   - 任务模板灵活配置（每天、每周指定星期、每 N 天周期），支持【全员共同任务（每台设备各一份）】与【单独指定孩子/设备（专属任务）】；
   - 今日任务快捷审批/驳回（明确标记来源孩子与设备），审批后金币精确注入对应孩子账本；
   - 独立查看每个孩子的宠物形象、装扮道具与金币流水。
5. **弱网与断网韧性**：断网状态清晰感知，只读数据本地秒开降级，写操作（审批、模板修改）严格防重防幂等。

## 二、总体架构与技术选型

### 2.1 技术栈选型

| 模块层级 | 选型 | 说明与选型优势 |
| :--- | :--- | :--- |
| **基础工程** | **Next.js 14 (App Router) + React 18 + TS** | Vercel 官方旗舰级框架，自带 Serverless API Routes、极速打包与内置静态优化。 |
| **移动端 UI 库** | **Ant Design Mobile (v5)** | 阿里移动端高品质组件库，专为手机交互深度优化，原生支持高清触控、手势回弹、以及专门的 `SafeArea` 安全区组件。 |

### 3.3 React 专属跨平台“添加到桌面”安装引导方案

系统采取 **双轨动态感知与引导机制**：

```text
                  用户通过手机浏览器打开 H5
                             │
            检测运行环境 (User Agent & Standalone)
                             │
        ┌────────────────────┴────────────────────┐
        ▼                                         ▼
  【已处于独立 App 模式】                     【普通浏览器模式】
  (`isStandalone === true`)                       │
        │                                         │
  隐藏所有安装提示，直接进入系统                   ┌───────┴────────────────────────┐
                                            ▼                                ▼
                                      【Android 浏览器】                【iOS Safari】
                                            │                                │
                               监听 `beforeinstallprompt`        检测 `isIos && !isStandalone`
                                            │                                │
                               拦截浏览器默认底部粗糙条，           在界面底部浮现 antd-mobile 气泡：
                               渲染定制组件：                    “点击下方分享按钮 ⎋，
                               【安装到桌面，秒速打开】            再选择‘添加到主屏幕’ ⊞”
                                            │                                │
                               点击触发 `prompt()` 原生弹窗        用户点击完成添加
```

#### 1) React Hook 封装：`usePWAInstall.ts`
```typescript
import { useState, useEffect } from 'react';

interface BeforeInstallPromptEvent extends Event {
  prompt: () => Promise<void>;
  userChoice: Promise<{ outcome: 'accepted' | 'dismissed' }>;
}

export const usePWAInstall = () => {
  const [deferredPrompt, setDeferredPrompt] = useState<BeforeInstallPromptEvent | null>(null);
  const [isInstallable, setIsInstallable] = useState(false);
  const [isStandalone, setIsStandalone] = useState(false);
  const [isIosSafari, setIsIosSafari] = useState(false);

  useEffect(() => {
    // 1. 判断是否已处于独立 App 模式
    const standaloneMode = 
      window.matchMedia('(display-mode: standalone)').matches ||
      (window.navigator as any).standalone === true;
    setIsStandalone(standaloneMode);

    // 2. 判断是否为 iOS Safari
    const ua = window.navigator.userAgent.toLowerCase();
    const isIos = /iphone|ipad|ipod/.test(ua);
    const isSafari = ua.includes('safari') && !ua.includes('crios') && !ua.includes('fxios');
    setIsIosSafari(isIos && isSafari && !standaloneMode);

    // 3. 监听 Android / Chrome 的安装准备就绪事件
    const handleBeforeInstall = (e: Event) => {
      e.preventDefault();
      setDeferredPrompt(e as BeforeInstallPromptEvent);
      setIsInstallable(true);
    };

    const handleAppInstalled = () => {
      setDeferredPrompt(null);
      setIsInstallable(false);
      setIsStandalone(true);
    };

    window.addEventListener('beforeinstallprompt', handleBeforeInstall);
    window.addEventListener('appinstalled', handleAppInstalled);

    return () => {
      window.removeEventListener('beforeinstallprompt', handleBeforeInstall);
      window.removeEventListener('appinstalled', handleAppInstalled);
    };
  }, []);

  const triggerInstall = async () => {
    if (!deferredPrompt) return;
    await deferredPrompt.prompt();
    const choice = await deferredPrompt.userChoice;
    if (choice.outcome === 'accepted') {
      setIsInstallable(false);
    }
    setDeferredPrompt(null);
  };

  return { isStandalone, isInstallable, isIosSafari, triggerInstall };
};
```

#### 2) 安装引导组件：`InstallPromptBanner.tsx`
结合 Ant Design Mobile 的 `NoticeBar`、`Popup` 或 `Button`：
- **Android 端**：在页面顶部展示微型 `NoticeBar`：“添加到桌面即可像 App 一样全屏秒开”，右侧放置小巧按钮【添加】，点击调用 `triggerInstall()`。
- **iOS Safari 端**：在屏幕底部弹出一个半透明指引卡片，配有向下的动态箭头指示 Safari 底栏中心的“分享”图标（`⎋`），文案提示：“1. 点击下方分享按键；2. 选择‘添加到主屏幕’”。支持勾选“7天内不再提醒”。

### 3.4 Service Worker 离线三级缓存策略（Vite PWA）

在 `vite.config.ts` 中配置 Workbox：

```typescript
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import { VitePWA } from 'vite-plugin-pwa';

export default defineConfig({
  plugins: [
    react(),
    VitePWA({
      registerType: 'prompt', // 发现新版本时提示用户，而非暴力强制刷新
      includeAssets: ['favicon.ico', 'icons/*.png', 'splash/*.png'],
      manifest: { /* manifest.webmanifest 内容 */ },
      workbox: {
        // 1. App Shell 核心静态资产预缓存 (HTML, JS, CSS, 字体等)，实现离线秒开
        globPatterns: ['**/*.{js,css,html,ico,png,svg,woff2}'],
        runtimeCaching: [
          {
            // 2. 宠物图片、商店物品图标：CacheFirst 优先缓存策略
            urlPattern: /\.(?:png|jpg|jpeg|svg|webp)$/,
            handler: 'CacheFirst',
            options: {
              cacheName: 'static-assets-cache',
              expiration: {
                maxEntries: 100,
                maxAgeSeconds: 30 * 24 * 60 * 60, // 缓存 30 天
              },
            },
          },
          {
            // 3. 今日任务与只读数据 API：NetworkFirst 策略
            // 网络顺畅时拉取服务端最新数据并更新缓存；弱网或离线超过 3 秒自动降级读取本地缓存
            urlPattern: /\/api\/v1\/(device\/tasks\/today|family\/summary|wallet)/,
            handler: 'NetworkFirst',
            options: {
              cacheName: 'api-runtime-cache',
              networkTimeoutSeconds: 3,
              expiration: {
                maxEntries: 20,
                maxAgeSeconds: 24 * 60 * 60, // 缓存 24 小时
              },
            },
          },
        ],
      },
    }),
  ],
});
```

### 3.5 离线状态降级与数据一致性机制

根据《产品方案.md》，**服务端是金币、任务状态的唯一权威**：
- **全局网络状态感知**：使用 React Hook 监听 `navigator.onLine`。当网络离线时，应用顶部展示 antd-mobile 的 `NoticeBar`（警告色）：“当前处于离线模式，正在展示最近同步的缓存数据”。
- **写操作离线保护**：
  - 家长审批（批准/驳回）、新建任务模板等高敏感操作，在离线状态下禁用按钮并给出 Toast 提示：“网络已断开，审批操作需与硬件设备实时对齐，请连接网络后重试”。
  - 杜绝因前端假数据造成与 ESP32 硬件设备金币不同步。

## 四、功能模块与页面流设计（支持多设备与多孩子）

家长端采用 **Ant Design Mobile 的 `TabBar`** 作为底部主导航，划分为 4 大模块：

```text
家长端 H5 (TabBar 4 大模块)
├── 1. 审批大厅 (Approvals)  ── 多孩子/多设备切换筛选、今日任务执行看板、置顶待审批卡片(标注来源设备与孩子)
├── 2. 任务管理 (Task Center)── 任务模板列表(标明全员/专属)、一键启停、新建规则(全员共同或指定设备)
├── 3. 宠物与金币 (Pet & Coins)── 多孩子无缝切换、专属宠物形象装扮与道具背包、独立金币流水
└── 4. 我的与设备 (Settings)   ── 微雪硬件设备列表(绑定第2/3台设备并指派孩子)、孩子档案管理、PWA桌面安装管理
```

### 4.1 核心页面交互设计

#### 页面 1：审批大厅（Home / TabBar 首页）
- **多孩子/多设备切换筛选栏（Tabs）**：
  - 支持快捷切换：`👥 全部孩子 (带待审角标)` | `👦 大宝天天` | `👧 二宝果果`；
  - 切换后即时过滤今日任务流与待审批卡片。
- **孩子与设备状态网格概览**：
  - 展示各孩子的专属宠物头像、金币余额、今日完成进度条（如 `3/5`）；
  - 展示对应的微雪设备在线/同步状态小徽标。
- **待家长确认任务（高优置顶区）**：
  - 孩子在各自 ESP32 设备上提交的任务，展示在卡片中；
  - **清晰标记来源**：展示具体归属孩子标签（如 `👦 天天`）与设备别名（如 `天天的书桌设备`）；
  - 使用 antd-mobile `Card` + `Button`：
    - 【批准发币】：点击后调用 `POST /task-instances/{id}/approve`，带入唯一操作 ID，金币精确发放至该孩子账户，触发粒子动效与轻震动；
    - 【驳回】：点击呼出 `Dialog` 弹窗，填写简短说明，任务退回为对应设备上的“待提交”状态。
- **今日任务执行列表**：
  - 按孩子分组呈现：待提交、免确认自动完成、已批准发放。

#### 页面 2：任务模板中心（TabBar 2）
- **模板卡片列表**：
  - 罗列当前家庭所有设定的学习/生活任务模板；
  - 每个模板卡片展示：任务标题、分发范围标签（`👥 全员共同任务` 或 `👤 天天专属`）、周期标签（如`每周一、三、五`）、奖励数（如`10 金币`）、确认类型；
  - 使用 antd-mobile `Switch` 支持一键【开启 / 暂停】。
- **新建 / 编辑任务模板表单（`Form`）**：
  - **布置范围（核心多设备支持）**：
    - 选项 A：`👥 全员共同任务`（每日为家庭下所有绑定的设备各自生成一份独立任务，孩子们各打卡各领奖）；
    - 选项 B：`👤 指定孩子专属任务`（多选勾选具体孩子，仅下发到该孩子的桌面屏幕）。
  - **任务名称**（输入框，如“阅读英语 15 分钟”）。
  - **任务说明**（文本域，简述完成标准）。
  - **金币奖励**：antd-mobile `Stepper` 步进器（初始推荐范围 5~15 金币）。
  - **确认方式**（`Selector` 单选）：`家长确认后发币` vs `孩子提交即发币`。
  - **重复频率规则**：`每天`、`每周指定星期`、`每 N 天`。
- **说明提示**：显式标注：“修改模板规则仅影响未来新生成的任务实例，不影响今日已生成的任务”。

#### 页面 3：宠物与金币中心（TabBar 3）
- **孩子切换控制器**：顶部提供 Segmented / Tabs 切换大宝、二宝，无缝浏览各自宠物。
- **孩子宠物状态视窗**：
  - 展示对应孩子在 ESP32 屏幕上的宠物形象、当前穿着的衣服道具（如天天穿水手服、果果穿恐龙睡衣）；
  - 道具背包预览：剩余食物数量、剩余水数量。
- **金币账户总览**：
  - 资产卡片：当前金币可用余额、今日赚取、累计支出。
- **金币收支明细列表**：
  - 独立记录该孩子的任务奖励入账与商城消费明细，防止多孩子账目混淆。

#### 页面 4：设备与家庭设置（TabBar 4）
- **微雪 ESP32 硬件设备管理（多设备支持）**：
  - 展示所有已关联的微雪开发板列表（设备别名、归属孩子、MAC 地址、在线状态）；
  - 点击【+ 绑定新设备】：弹出配对窗口，输入开发板屏幕的 6 位短期配对码，选择归属的孩子并设置别名，即可完成绑定；
  - 提供单台设备的【解除绑定】二次确认弹窗。
- **孩子档案管理**：
  - 罗列家庭孩子列表，支持修改昵称，支持【+ 添加孩子档案】。
- **家庭信息设置**：家庭时区设置（默认 `Asia/Shanghai`）。
- **PWA 与桌面快捷方式管理**：
  - “添加应用到桌面”手动说明与触发按钮；
  - “检查新版本”按钮（触发 Service Worker 检查）。
  - 清理本地缓存数据。

## 五、移动端原生体验与交互规范

借助 **Ant Design Mobile** 的设计规范，全面抹除普通 Web 页面的“网页感”：

### 5.1 安全区组件（Safe Area）适配
Ant Design Mobile 自带 `SafeArea` 组件，完美处理全面屏刘海与底部虚拟横条：
```tsx
import { SafeArea, NavBar, TabBar } from 'antd-mobile';

export const Layout = () => {
  return (
    <div className="app-container">
      {/* 顶部适配 iPhone 灵动岛 / 刘海 */}
      <SafeArea position="top" />
      <NavBar>学习宠物助手</NavBar>

      <main className="main-content">
        <Outlet />
      </main>

      {/* 底部 TabBar 搭配底部安全区 */}
      <TabBar className="bottom-tabbar">
        {/* Tab 选项 */}
      </TabBar>
      <SafeArea position="bottom" />
    </div>
  );
};
```

### 5.2 杜绝“网页感”的移动端全局样式
在 `src/index.css` 中注入：
```css
/* 1. 禁用双击缩放与滚动橡皮筋穿透 */
html, body {
  touch-action: manipulation;
  overscroll-behavior-y: none;
  -webkit-tap-highlight-color: transparent;
}

/* 2. 禁止用户长按文字呼出系统复制菜单（除输入框外） */
* {
  -webkit-touch-callout: none;
  -webkit-user-select: none;
  user-select: none;
}
input, textarea {
  -webkit-user-select: auto;
  user-select: auto;
}
```

### 5.3 实体级震动反馈（Haptic Feedback）
在家长点击“批准发币”、“驳回”、“绑定成功”等重要操作时，调用移动端振动 API：
```typescript
export const triggerHaptic = (duration = 15) => {
  if (typeof window !== 'undefined' && 'vibrate' in navigator) {
    navigator.vibrate(duration);
  }
};
```

## 六、前后端 REST API 契约（对齐《产品方案.md》）

所有接口基于 RESTful HTTPS，Header 自动携带 `Authorization: Bearer <Token>` 与 `X-Request-Id`（幂等操作 ID）。

| 模块 | 方法 | 路径 | 核心入参 / 说明 |
| :--- | :--- | :--- | :--- |
| **设备配对** | `POST` | `/api/v1/device/pair` | `{ "pairCode": "849201" }` 绑定设备 |
| **设备解绑** | `DELETE`| `/api/v1/device/binding` | 解除当前家庭与硬件设备的绑定 |
| **今日看板** | `GET`  | `/api/v1/parent/tasks/today` | 获取今日待审批、待完成、已完成列表 |
| **任务审批** | `POST` | `/api/v1/task-instances/{id}/approve` | `{ "requestId": "uuid" }` 批准并发金币 |
| **任务驳回** | `POST` | `/api/v1/task-instances/{id}/reject` | `{ "reason": "未完成", "requestId": "uuid" }` |
| **模板列表** | `GET`  | `/api/v1/task-templates` | 获取家庭下所有任务模板 |
| **新建模板** | `POST` | `/api/v1/task-templates` | `{ title, rewardCoins, frequency, confirmType, ... }` |
| **更新模板** | `PUT`  | `/api/v1/task-templates/{id}` | 更新任务模板参数 |
| **启停模板** | `PATCH`| `/api/v1/task-templates/{id}/status` | `{ "enabled": true/false }` |
| **金币流水** | `GET`  | `/api/v1/wallet/transactions` | 分页查询金币入账与消费记录 |
| **宠物状态** | `GET`  | `/api/v1/family/pet-summary` | 获取宠物装扮、道具库存与最后同步时间 |
