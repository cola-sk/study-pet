# 家庭设备配对（待部署与联调）

家长用 Supabase 邮箱密码登录后，每个账号拥有一个固定的 6 位数字配对码；生成时会使用数据库唯一约束检查重复并在冲突时重新生成。设备先加入家庭，再由家长在网页选择一个属于该家庭的孩子；选择后设备才可以读取该孩子的钱包。配对码相当于家庭加入凭据，请不要公开分享。每台设备另行生成随机 256 位访问凭据，服务端只保存 SHA-256 摘要。

## 部署顺序和数据影响

1. 备份线上数据库。先在正确的 Supabase 项目按顺序查看并执行 `supabase/migrations/20261112_device_api.sql` 和 `supabase/migrations/20261113_account_pairing.sql`、`supabase/migrations/20261114_six_digit_pairing.sql`。第二个脚本会对项目九张业务表启用 RLS 并撤销匿名及普通登录用户的直接表权限；此前依赖浏览器直接访问数据库的功能将停止，**旧版家长端的任务等功能仍属于本地演示，尚未迁移**。在生产使用前必须先确认这一影响。
2. 服务器配置 `SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY` 与 `PAIRING_CODE_SECRET`。后者需要固定的 32 字节随机值，可在本机运行 `openssl rand -hex 32` 并将结果安全地填入部署平台的服务端环境变量。不要将服务端密钥放入代码、聊天、浏览器环境变量或设备中。更改该值会更换所有人的配对码。
3. 部署家长端/API，确保 Supabase 邮箱密码登录已启用。首次登录会为未关联的账号新建家庭；若线上已有人手工录入的家庭数据，必须在首次登录前将现有 `parents.auth_user_id` 关联到正确的 Auth 用户，否则新建家庭不会自动继承旧数据。
4. 重新编译并烧录设备固件，连接已配置的 2.4 GHz Wi-Fi。在家长端“家庭设备”中的账号区登录/注册并查看配对码；设备点 `Pair` 输入 6 位码，然后在家长端刷新设备、添加孩子并选择其归属。

## 验证及限制

设备加入家庭后会显示等待选择孩子；家长选择后，设备定时获取真实钱包余额。当前真实商店接口尚未完成，配对后喂食和喝水的扣款暂不可用。其他家长端业务页面和设备任务页面尚未完成真实接口接线；不要将本地演示的数据当作线上数据。

密码和设备凭据不会写入日志；当前设备凭据保存在 NVS，实际硬件尚未启用 Flash 加密，因此用于生产前仍需完成安全启动、加密、凭据撤销与重配流程。6 位固定码空间较小：接口将所有配对尝试限制为每 15 分钟最多 20 次、同一来源最多 5 次；达到限制后需等待窗口结束。该全局限流可能影响其他用户，正式大规模使用前应增加防滥用、可撤销或轮换配对码及更稳妥的限流策略。当前码暂无自助重置。完整线上配对尚未测试：需要部署配置、执行迁移、实际登录和设备操作后确认。
