# 真实接口实施状态

## 已实现的服务端接口（未部署前仅在本地）

- `GET /api/v1/device/tasks/today`：设备 bearer 凭据，按设备所属孩子与家庭时区读取当天已生成任务。
- `GET /api/v1/wallet`：设备 bearer 凭据，读取所属孩子的数据库余额。
- `POST /api/v1/task-instances/{id}/submit`：设备 bearer 凭据和稳定 `requestId`；数据库事务锁定任务，自动确认时发币和流水一起提交，家长确认时仅提交审批。同一 requestId 的重试可返回之前状态。
- `GET /api/v1/family/children`、`POST /api/v1/family/children` 和 `GET /api/v1/task-templates`：Supabase 邮箱密码登录后，用 access token 识别家长并按其关联家庭隔离。

上述接口使用服务器专用 `SUPABASE_SERVICE_ROLE_KEY`；家长 token 使用 Supabase Auth 校验；设备 token 的 SHA-256 摘要由数据库匹配。密钥只能设置在服务端环境，绝不能放到网页、固件或代码库。API 目前不提供自动注册设备或生成配对码。

## 数据库迁移及部署

`supabase/migrations/20261112_device_api.sql` 是增量迁移，不会创建家长或设备关联。执行前备份，并确认现有应用的访问策略。配置服务端 `SUPABASE_URL` 和 `SUPABASE_SERVICE_ROLE_KEY` 后部署；家长的 `parents.auth_user_id` 必须与 Supabase Auth 用户关联，设备的 `api_token_hash` 必须匹配它的高随机性凭据，设备必须处于 paired 并关联正确孩子和家庭。不要在聊天或日志中传播设备 token。尚未实现安全的配对流程和自助绑定，不能将当前接口当作已完成配对。

**上线前必须处理现有权限：** 旧的 `schema.sql` 对 `anon` / `authenticated` 授予了所有表和函数权限。本次增量迁移未移除这些历史授权，API 的身份检查无法阻止客户端直接访问数据库。需要迁移所有家长端读写至认证服务，检查并启用 RLS、收回不必要的表和函数权限，再验证家庭之间无法互访。切勿先对现有运行中的数据库盲目执行全局收权，以免中断现有数据访问。

## 设备钱包接入进度

固件在配置 `STUDY_PET_DEVICE_TOKEN` 后，以设备凭据访问真实 `/api/v1/wallet`，读取成功时更新屏幕积分。未取到真实余额时显示 `-- credits`；真实商店接口尚未完成，因此配置凭据后喂食和喝水的消费按钮会提示不可用，避免本地假扣款。未配置设备凭据时仍为演示模式。设备凭据目前使用 menuconfig 编译进固件，尚未实现安全配对或加密保存，不应当作最终生产方案。当前接口与固件尚未部署、迁移或完成配对验证。
