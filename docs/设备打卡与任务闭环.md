# 设备打卡与任务闭环

## 使用步骤

1. 家长登录家长端，在「宝贝与小宠」添加孩子，再通过「家庭设备」配对设备并关联孩子。
2. 在「任务管理」创建任务，填写标题、可选说明、金币数量、频率、参与孩子和日期范围，选择「打卡立即发币」或「家长表扬后发币」。每个家庭最多保留 50 个未移除的模板（含停用模板）。
3. 设备联网后，点击首页的 **Today** 进入今日任务，点击任务查看内容，再点 **Complete task**。列表每页最多显示 10 项，可以翻页。标题和说明支持常用中文，屏幕上的状态及操作为英文。
4. 立即发币任务确认后更新金币并触发小狗开心动画。需要确认的任务显示 **Waiting for parent**；家长在「打卡审批」点击批准后，奖励才会到账。也可以选择「再试一次」并填写提示，孩子在设备重新打卡。
5. 设备定期同步任务和金币，设置页也可手动同步金币。家长端在前台时会定期刷新，也支持下拉刷新审批页。

日期以家庭时区计算。每天、指定星期或每隔 N 天的任务在家长端或设备请求当天任务时按需生成，无需定时任务。模板内容和奖励保存为当天任务的快照：修改、停用、移除模板不会改写已经生成的当天任务或历史记录。

旧版只保存在浏览器中的任务会显示为「浏览器旧任务 · 待导入」。请逐个打开检查，选择本家庭的宝贝后保存。旧版本的演示模板不会导入。

## 异常和重试

- 设备运行期间，打开已加载过的任务页会立即显示最近一次同步的缓存，并在后台刷新；离线或刷新失败时仍可查看缓存和其日期。正在刷新或离线时，需先同步成功才能提交新的打卡。设备重启后会重新联网加载，任务列表缓存不会跨重启保留。

- 正在确认的一笔设备打卡会先保存到设备本地，再发送到服务器；断网、超时或重启后使用原请求编号重试，不会因为重试重复发币。同一时间只处理一笔尚未确认的打卡。
- 点击完成后如果断网，已保存的请求会排队重试；设备提示离线、无法加载列表时请先恢复网络。任务结果以服务器为准，未确认不会提前增加金币。
- 未提交成功且已过当天的任务不能补打；已经成功提交但响应丢失的请求，跨日重试仍可查询此前结果。已提交、待审批的任务即使跨日，家长仍可以审批。
- 如果网络暂不可用或设备还未绑定孩子，任务页会给出提示。确认设备 Wi-Fi、家庭配对及孩子关联后点击刷新。
- 长时间显示确认中时检查 Wi-Fi 与家长端部署；请勿反复重置设备数据。审批失败时家长端会提示错误，余额以服务端结果为准。

## 上线和验证

本功能需要依次应用此前迁移与 `supabase/migrations/20261117_task_checkins.sql`，再部署 `apps/parent-h5` 服务并烧录 `apps/pet-device`。迁移是增量操作，不清除现有任务、家庭、孩子或金币；从旧版本升级时仍应按既有备份策略执行。

建议用一个测试任务验证：

1. 家长设置一个今日、1 金币、需确认的任务。
2. 孩子在设备提交；确认显示等待家长，家长端出现待审批记录，金币未变化。
3. 家长批准；设备与家长端同步后余额增加 1。反复点击或刷新，余额不能再次增加。
4. 再创建一个立即发币任务，完成后检查余额只增加一次。

也可以打开 `apps/pet-device/preview/index.html`，在浏览器中体验模拟任务和审批；预览不连接线上数据库，金币只是本地演示数据。
