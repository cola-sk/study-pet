# 设备联网与预置数据清理

## 当前实现与限制

项目原有的家长端主要使用浏览器本地数据。任务创建、孩子管理与设备配对并没有完整接入服务端；不要将本地数据理解为 Supabase 数据。线上 `https://keep.1203.fyi` 能打开，但 `/api/v1/device/tasks/today` 和 `/api/v1/wallet` 当前返回 404。设备固件目前只增加了通过 HTTPS 访问 `/api/device/health` 的连通性探测，不会声称任务或金币已经同步。需要部署新版本后这个探测地址才会生效。

新的安装不再自动填充示例孩子、任务、设备及商品；升级本地浏览器存储时只清除旧版固定 ID 的示例。该本地变更不会清理线上数据库。

## 手动清理数据库

确认进入正确的 Supabase 项目，先查看 `supabase/manual/cleanup_seed_shop_items.sql`，然后在 SQL Editor 执行。该脚本只删除六条固定 ID 且名称、类别和价格仍与示例一致的商品；正在被宠物穿戴的商品会保留。数据库中其他孩子、任务、余额、设备和商品不受影响。执行结果通过 `RETURNING` 显示。现有 schema 的初始数据部分仅发现这些商品；如数据库中还有其他示例，请先识别后针对性处理。

## 配置设备 Wi-Fi

使用 2.4 GHz 网络 `S26`。在自己的电脑 VS Code 终端运行：

```bash
. ~/esp/esp-idf/export.sh
cd /Users/liuzhe.x/coding/study-pet/apps/pet-device
idf.py menuconfig
```

进入 `Study Pet network`，填写 SSID `S26` 和密码，保存退出。密码保存在本地被 Git 忽略的 `sdkconfig`，并会编译进固件；不要提交该文件或分享包含密码的固件。没有配置 SSID 时设备不会联网。之后执行 `idf.py build`，并在连接设备后用 `idf.py -p /dev/cu.usbmodem1101 flash monitor`；串口可能变化。退出日志用 Ctrl+]。

固件连接 Wi-Fi、通过 NTP 获取时间后，每 60 秒访问 `https://keep.1203.fyi/api/device/health`，使用证书链验证。日志中的 HTTP 200 只说明新部署的探测接口可访问，不表示已配对或业务同步成功；404 表示线上还没有该版本。Wi-Fi 与部署环境正常后再排查 TLS、DNS 和网络时间。

## 尚需实现

真实的设备注册与身份凭据、家长登录和家庭隔离、设备与孩子的绑定、任务生成及提交、钱包和购买的事务/幂等、后端同步以及安全上线。已有 schema 给 `anon` 授予全部表及函数权限，不能作为生产数据访问方案；应先实施认证和行级权限，再接入真实用户数据。不要把 Supabase service-role key 写进设备固件。
