# 邮箱验证与登录

注册后的流程：填写邮箱和密码 → 打开确认邮件 → 显示“邮箱验证成功” → 点击“前往登录” → 使用邮箱和密码登录家长端。

邮件链接只确认邮箱，不会自动登录或替换当前浏览器里已有的登录账号。成功页不会自动跳转。验证结果通过 Supabase Auth 核实，回调凭据随即从地址栏移除，不写入登录存储。

## 页面行为

- `/auth/verified`：独立验证结果页，不显示家庭数据或导航栏。
- 链接过期或已使用：提示已验证者可以直接登录，尚未验证者重新获取邮件。
- 无效链接或直接打开成功页：提示从邮件打开完整链接，不直接显示成功。
- 网络失败：提供“重试验证”。
- 成功后在当前历史记录中保留 30 分钟展示标记，刷新可以继续看到成功提示；此标记不提供任何登录权限。
- 兼容此前跳到首页的注册邮件：首页先转交验证页，再加载家长端。

## 部署配置

Supabase Authentication → URL Configuration：

- Site URL：`https://keep.1203.fyi`
- Redirect URLs：保留 `https://keep.1203.fyi/`，新增 `https://keep.1203.fyi/auth/verified`、`https://keep.1203.fyi/auth/reset-password`。

代码注册时通过 `emailRedirectTo` 指定验证页。可选环境变量 `NEXT_PUBLIC_SITE_URL` 是部署站点的完整根地址，默认 `https://keep.1203.fyi`，修改后需要重新构建。Supabase 继续开启邮箱确认，保留默认邮件中的确认链接即可。

## 本地验证

```sh
node --test apps/parent-h5/tests/emailVerification.test.cjs
pnpm --filter parent-h5 build
```

自动测试覆盖已确认邮箱、缺失或无效凭据、错误回调、未确认邮箱、服务异常，以及验证时不保存会话。浏览器成功流程可以使用隔离环境和模拟 Auth 响应验证；完整邮件流程需在正式部署后通过新注册邮件验证。

## 找回密码和重发邮件

登录页提供“忘记密码”和“重发验证邮件”。恢复邮件回调 `/auth/reset-password`，使用独立内存会话验证身份并设置新密码，成功后返回登录。登录中的家长也可在“家庭设备 → 账号与设置”发起修改密码。新密码为 8–72 个字符，可显示密码并确认两次输入一致；过期链接需重新申请。
