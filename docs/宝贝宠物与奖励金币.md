# 宝贝、小宠与奖励金币

## 本次变化

- 家长端“宝贝与小宠”统一展示真实孩子资料、专属小二哈、金币和绑定设备。家庭设备页保留设备管理入口，通过“去管理”进入宝贝页面。
- 可以先添加宝贝，再绑定设备；也可以在添加设备的三步引导中创建宝贝。
- 宠物页不再读取本地演示钱包。没有孩子时显示引导空状态，不再拼接 `undefined的小宠`。
- “奖励金币”支持每笔 1–10000 个整数金币和最多 200 字的原因；余额和流水在同一数据库事务中写入。
- 超时后会保留本次请求 ID，重试确认不会重复发币；该待确认记录按家庭保存在当前浏览器，确认前不支持修改数量。
- 设备等待选择孩子时每 3 秒检查钱包，收到合法余额（包括零余额）即清除配对提示；日常余额每 5 秒同步。以上间隔不含网络请求耗时。网络失败按 10、20、40、60 秒退避，身份失效时每 60 秒重试。

## 上线步骤

1. 在 Supabase SQL Editor 执行 `supabase/migrations/20261115_parent_credits.sql`。先前的账号与配对迁移应已执行。本次只新增奖励函数、流水操作者字段及唯一索引，不改动现有余额。
2. 重新部署家长端和 API，无需添加新环境变量，继续使用现有 Supabase 配置。
3. 更新设备固件。新固件保留 NVS 中的设备身份和 Wi-Fi 配置，无需重新配对。
4. 登录后进入“宝贝与小宠”，选择孩子，点击“奖励金币”。确认网页余额与流水更新，并等待已联网设备显示新余额。

未更新 API 时，待选择孩子的设备仍可能收到旧接口的 401 响应，从而使用较长的重试间隔；需前后端一起更新。

## 接口与权限

- `GET /api/v1/family/children`：当前家庭的孩子及关联宠物记录、设备列表。
- `GET /api/v1/family/children/:id/wallet`：家长认证，读取所属家庭孩子余额、最近 50 条流水和商品目录。
- `POST /api/v1/family/children/:id/credits`：家长认证，请求 `{ amount, requestId, note? }`；家庭与操作者由登录身份确定。
- `GET /api/v1/wallet`：设备认证。已加入家庭但未分配孩子返回 `409 { state: "awaiting_child" }`；已分配返回真实余额。
- `grant_parent_credits` 仅允许 service_role 调用，锁定孩子余额、校验家庭归属、原子更新余额并写入 `parent_grant` 流水。家庭与请求 ID 唯一，同 ID 参数冲突会拒绝。

宠物外观当前统一为小二哈；数据库中的喂养计数若不存在，页面只显示陪伴说明，不伪造计数或健康状态。真实商店扣款及其设备接口仍待实现，配对设备的喂食／喝水暂显示 Shop unavailable。任务管理、打卡审批尚未整体迁移到真实 API，本次不会改动这些页面的数据逻辑。
