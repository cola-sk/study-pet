# 学习任务养成宠物桌面设备方案

> 产品方案稿。支持一个家庭关联多孩子、多台微雪 ESP32-S3-Touch-LCD-2.8 桌面设备；支持全员共同任务与单独设备专属任务。

## 一、产品定位

家长设置学习或生活习惯任务，孩子在桌面设备上查看并提交完成，获得虚拟金币，再用金币购买食物、水和服装与宠物互动。

核心闭环：家长创建任务（全员或指定设备） → 系统按频率为各设备生成每日任务 → 孩子在各自屏幕提交 → 家长确认后向对应孩子发放金币 → 孩子购买并使用物品 → 宠物展示反馈。

设计原则：鼓励过程，不通过宠物生病、死亡或扣金币制造压力；不设计现金充值、随机抽奖和排行。设备无法核实孩子是否真正完成任务，需要家长确认或基于信任。

## 二、功能规划

| 角色 | 功能 |
| --- | --- |
| 家长 | 手机浏览器登录，关联多台设备、管理多个孩子档案、设置任务（全员共同/单独指派）及奖励、按设备/孩子确认完成、查看历史和独立金币流水 |
| 孩子 | 在专属设备上查看今天的任务、提交完成、查看个人余额、购买和使用物品、观看宠物动画 |
| 系统 | 按设备生成任务实例、同步设备状态、记录各孩子金币和库存、处理网络重试 |

优先做手机网页（PWA），支持离线安装到手机主屏幕，减少原生 App 或小程序开发成本。设备上不提供任务规则修改入口。每台微雪设备与一个孩子 1:1 专属绑定，记录孩子独立的宠物与资产。首版暂不做社交、摄像头、AI 陪伴、付费和电池。

### 1. 家长与任务

家长创建账户和家庭，可添加多个孩子档案（如大宝、二宝）；微雪设备显示短期 6 位配对码，家长在网页输入配对码并选择归属孩子完成绑定。任务支持名称、说明、起止日期、金币奖励、确认方式、启停、重复频率及**布置范围**：
- **重复频率**：每天、每周指定星期、每 N 天（从指定起始日期起算）。
- **布置范围**：
  - **全员共同任务**：系统每日自动为家庭下所有绑定的设备各生成一份独立任务实例，孩子们各自在自己设备上打卡领奖；
  - **指定设备专属任务**：仅向选中的设备/孩子下发该任务（如大宝的“英语听力”、二宝的“拼音练习”）。

系统按家庭时区生成任务实例，每个模板每天对每个目标设备最多一个实例，首版不支持跨日补做。默认时区 Asia/Shanghai，可配置；以服务端时间为准。已生成的实例保存原有奖励和确认方式，修改规则只影响未来尚未生成的实例。

确认方式包括“家长确认后发币”（默认）和“孩子提交即发币”。家长可批准或驳回待确认任务（审批大厅清晰展示来源孩子与设备名称）；驳回后恢复可提交并保留记录。当天未完成任务到期关闭；有效期内提交但尚未确认的任务可在之后处理。发币精确打入提交该任务的孩子账户中，首版不撤销已经发放的金币，避免影响已消费余额。

### 2. 设备与宠物

- 首页显示宠物、今日任务进度、金币和联网状态；任务列表展示待完成、待确认和已完成状态，提交前二次确认防误触。
- 商店展示食品、水、衣服及价格。食物和水是消耗型互动道具；衣服永久拥有，可穿脱。首版不设饥饿和口渴的持续衰减或惩罚。
- 设置包括 Wi-Fi 配网、配对码、亮度、声音开关及设备信息。恢复出厂后需重新绑定；家庭数据仍保留在服务端。
- 断网时可以查看缓存的当天任务并提交，界面显示“待同步”，不提前显示金币到账；联网后重试。首版购买和使用物品必须在线。

### 3. 任务与经济规则

任务实例状态：`待完成 → 待确认 → 已完成`；免确认任务直接从待完成进入已完成；驳回时恢复待完成。离线提交在服务端成功处理前只显示待同步，服务端可因过期、无权限或已处理而拒绝，并向设备返回原因。

金币只是产品内虚拟积分，不可提现或转账。试用初始参数：每项任务 5～10 金币，食品或水 5～15 金币，衣服 30～60 金币。比如每天完成两项各 10 金币的任务，三天可以兑换 60 金币的衣服；根据家庭试用调整节奏。

每个任务实例最多发奖一次；每次加减金币写流水，余额不足不能购买。衣服已拥有时禁止重复购买，消耗品可重复购买。服务器原子处理余额和库存，重复操作及网络重试不能重复发奖、扣款或发货。

## 三、典型使用流程

1. 家长创建“阅读 15 分钟”，设置周一至周五出现、奖励 10 金币、需要家长确认。
2. 周一设备同步到任务，孩子阅读后点击完成；设备显示待确认，余额不变。
3. 家长确认后服务端更新任务、余额和流水；设备同步并播放奖励动画。
4. 孩子花 10 金币买水，服务端扣款并增加库存；点击使用后库存减少，设备播放喝水动画。
5. 如设备断网，缓存内的任务可提交并进入持久化队列；恢复联网后按原操作 ID 重试，服务端返回结果。首次未联网校时且没有可信缓存时，设备提示联网同步，不猜测当天任务。

## 四、已购硬件适配：微雪 ESP32-S3-Touch-LCD-2.8

依据 [微雪产品文档](https://docs.waveshare.net/ESP32-S3-Touch-LCD-2.8/) 和[版本资料及示例](https://docs.waveshare.net/ESP32-S3-Touch-LCD-2.8/Resources-And-Documents/)（2026-11-12 查看），该板足以验证首版核心流程，不需要另购屏幕或触摸模块。请注意产品名末尾没有 B 或 C，不能直接套用其他型号资料。

| 项目 | 板载规格或方案影响 |
| --- | --- |
| 主控和存储 | ESP32-S3 双核最高 240 MHz，16 MB Flash、8 MB PSRAM，满足原方案建议规格；仍需测量中文字体、图片和动画的实际占用 |
| 屏幕 | 2.8 英寸、240 × 320 电容触摸屏，ST7789 显示驱动；界面以少字、大按钮、分页为主，实际字体和触摸目标需上板测试 |
| 触摸版本 | V1 使用 CST328，V2 使用 CST3530；微雪说明 2026-06-05 后出货切换 V2，但必须以板背标签为准。使用对应版本的厂商示例，不要混用触摸驱动 |
| 联网 | 2.4 GHz Wi-Fi 和 BLE；家中需有 2.4 GHz 网络。BLE 配网可作为后续选项，不必先做 |
| 音频 | 板上有 PCM5101 音频解码、功放和音量旋钮，文档列出 8Ω 2W 喇叭接口；实际是否随板附带喇叭请核对配件。优先跑通厂商音频示例，软件可静音 |
| 时钟 | PCF85063 RTC；厂商说明断电保持时钟需连接可充电 RTC 电池并设置时间。首版以服务端校时为准，无需依赖 RTC 保持时间 |
| 电源 | Type-C 用于烧录及日志；板载系统电池充电管理及接口。首版仍建议 USB 供电，电池和充电需单独做安全与续航验证 |
| 其他 | 板载 QMI8658 六轴传感器、Micro SD 卡座；首版不需要。I2C GPIO10/11 已连接板载器件，不能作为普通 GPIO 随意占用 |

使用 LVGL 制作竖屏原型：首页显示宠物、金币和一个明显的“今日任务”入口；任务列表每屏 2～3 项，商店每屏少量商品。240 × 320、RGB565 的完整单帧约 150 KiB（240 × 320 × 2 字节），实际采用单缓冲、双缓冲或局部刷新应依据厂商示例、PSRAM 和流畅度实测决定。首版静态图或少量帧动画即可，避免预设高帧率。

样机成本不再包含另购屏幕，仍需考虑电源、外壳及实际是否附带喇叭；采用已购价格和配件清单估算，不沿用之前的泛化报价。外壳避免尖角、裸露导线和易脱落小零件；量产须另做安全和可靠性认证。

## 五、技术架构

```text
家长手机网页 ── HTTPS ──┐
                      ├── 应用服务 ── 数据库（任务、金币流水、库存）
ESP32-S3 设备 ── HTTPS ─┘
```

- 固件：ESP-IDF、FreeRTOS；屏幕界面可采用 LVGL。拆分屏幕/触摸驱动、任务页面、宠物动画、网络同步、离线队列和本地存储；具体驱动依选定开发板确认。
- 家长端：响应式 Web 页面，技术栈按团队熟悉程度选择。
- 服务端：REST API + PostgreSQL，负责用户权限、任务生成、确认、金币和库存。首版在线时每 30～60 秒拉取，提交后立即刷新，实际延迟和功耗需测量。开发时可运行在电脑上，设备通过局域网地址访问；生产环境使用 HTTPS。
- 数据：家庭、家长、孩子、设备、任务模板、任务实例、提交记录、金币账户及流水、物品库存、操作去重记录。余额快照与流水在同一数据库事务中更新，服务端是唯一权威。
- 参考接口：`POST /device/pair`、`GET /device/tasks/today`、`POST /task-instances/{id}/submit`、`POST /task-instances/{id}/approve`、`GET /wallet`、`POST /shop/purchases`、`POST /inventory/{itemId}/use`；目前只是设计草案。
- 每个操作带稳定操作 ID，服务端对设备及操作 ID 做唯一约束；发奖、购买和消耗在事务中检查状态并记录结果，重试返回首次结果。离线队列重启后保留，失败原因需展示。

## 六、安全和隐私

家长登录、家庭隔离及服务端权限校验是基本要求。配对码短时有效、一次使用并限制尝试次数；设备获得独立、可撤销的凭据，凭据不写日志。通信使用 TLS；Wi-Fi 配置和设备凭据保存在受保护的存储中。结合实际硬件与发布流程评估安全启动、Flash 加密和签名更新；上线前落实限流、备份、数据删除与密钥轮换。涉及儿童数据时遵循适用法律，尽量少收集并取得监护人所需同意。

## 七、实施阶段和验收

| 阶段 | 交付及验收 | 粗略工作量（单人，非承诺） |
| --- | --- | --- |
| 技术验证 | 编译烧录、串口输出；点亮屏幕、验证触摸及 2.4 GHz Wi-Fi | 3～7 天 |
| 端到端闭环 | 家长创建任务，设备提交，家长确认，金币只到账一次 | 1～2 周 |
| 宠物与商店 | 购买、使用道具，展示宠物反馈，余额和库存一致 | 1～2 周 |
| 稳定性与试用 | 断电恢复、离线重试、配网、基础安全和家庭试用 | 1～2 周 |

重点验收：重复点击或网络重试只发一次金币；余额不足无法购买；断网提交状态准确且恢复后安全同步；跨日和每 N 天规则按家庭时区执行；不同家庭的数据相互隔离；设备断电后队列不丢失。

## 八、待确认
