# 设备金币刷新与商店互动

## 当前已实现

设备每 5 秒自动读取真实余额，等待分配孩子时每 3 秒检查，间隔不含请求耗时。因此家长奖励金币后，孩子不需要手动刷新才能收到。

本次补充了手动入口：点击右上角金币区域 `Tap to sync`，立即提交同步请求。等待中显示 `Syncing...`，完成显示 `Synced`，失败显示 `Retry sync`，不把余额改为零。重复点击在请求结束前禁用。未配对时点击可进入配对页；网络初始化未完成时显示 `Try again`。刷新不发放金币，仅读取服务器余额。

设备 Feed / Water 目前是写死的演示入口，真实配对后主动禁止本地扣币，显示 `Shop unavailable`。真实购买 API 尚未实现，不能通过隐藏提示或手动修改本地余额来解决。

家长端已经读取真实 `shop_items`，不会注入预制商品；清理后的数据库没有商品时目录为空。本次增加了明确的空状态和兑换功能尚未开放的说明。

## 建议采用的交互规则（待实现）

将“互动类型”和“可购买商品”分开表达。放射菜单保留少量直观动作，同类商品放在下一层选择，避免 240×320 屏幕挤满商品。

| 设备操作 | 商品来源 | 点击后的行为 |
| --- | --- | --- |
| Feed / 喂食 | 上架且设备支持的 food 商品 | 只有一个时显示名称与实际价格并可直接购买；多个时进入食物选择页 |
| Water / 喝水 | 上架且设备支持的 water 商品 | 只有一个时显示实际价格；多个时进入饮水选择页 |
| Dress / 换装 | 上架且固件具备对应资源的 clothes 商品 | 选择装扮并购买；没有配套画面资源时不开放 |
| Pet / 抚摸 | 免费互动，不属于商品 | 直接播放陪伴动作 |
| Sleep / 睡觉、Wake / 叫醒 | 免费互动，不属于商品 | 切换休息状态 |

商店是付费用品和价格的唯一来源。同一类别可以有多个商品，因此商品与放射菜单入口不必一一对应；每个可购买商品必须映射到固件支持的动作或装扮资源。商品名称、价格不在设备写死。后台增加未知动作，不能让设备自动获得新动画。

首版建议“购买即使用”：买食物立即喂食、买饮水立即喝水，不额外增加背包购买和使用两个步骤。免费互动由设备独立提供，即使没有商品仍然可用。

目录为空或某类别没有可用商品时，不显示该类别的可购买入口；目录加载失败应提示重试，与“没有商品”区分。商品较多时按类别分页显示，不把所有商品塞进放射菜单。

## 购买的业务约束（待实现）

1. 设备获取真实可用商品目录，展示服务端价格；家长端展示同一目录并支持维护上架状态、价格及支持动作。
2. 设备提交商品 ID 和本次操作的唯一请求 ID，服务端根据设备身份确定家庭和孩子。
3. 服务端校验商品可用、固件支持、余额足够，在一个事务内扣币、记录流水并更新宠物喂养或装扮状态。价格只从数据库读取。
4. 成功响应携带最新余额和明确动作，设备更新 credit 并播放吃饭／喝水，然后开心。失败不播放购买成功动画、不扣本地余额。
5. 请求超时要用原请求 ID 查询或重试，防止重复扣款，结果未确认前禁用新的购买。

目前商品表是全局目录，若要让每位家长自行定价和维护商品，需要补充家庭归属与权限隔离；还需要上架字段、动作映射、商品管理 API、设备目录 API、幂等购买事务和设备商品选择页。以上是下一阶段的完整范围，本次手动刷新并未声称已完成这些购买功能。
