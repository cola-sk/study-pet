# 一级商品菜单与真实兑换

## 规则

每个家庭拥有同一份商品目录，最多 10 个可用商品，包含两个内置商品：Water 默认 1 credit（喝水），Food 默认 2 credits（喂食）。因此最多可添加 8 个自定义商品。内置商品不能删除或更名，可以调整价格。

家长在“宝贝与小宠 → 小宠商店”新增、编辑或删除商品。自定义名称支持 1–12 个汉字、英文、数字、空格和 `_ . -`，价格支持 1–10000 的整数 credit，可选择吃东西、喝水、陪伴玩耍、开心庆祝四种已有动画。

设备点击小狗后，所有商品和 Sleep、Pet 直接出现在同一层的放射菜单；无需分类、二级列表或购买确认页。免费操作不占 10 个商品的名额。菜单根据操作总数调整按钮大小与位置：2–4 个使用 88×54，5–6 个使用 84×52，7–8 个使用 76×48，9–12 个使用 72×44，围绕小狗排列。当前 Water、Food、Cookie 加免费操作共有 5 个，使用 84×52；Cookie 可完整显示。更长的名称在设备滚动显示，价格固定展示。设备新增了中文字体。

商品名称可以自由想象，但新建商品不会自动生成新的动画。衣服和自定义画面资源不在本次范围。

## 同步与购买

- 余额每 5 秒自动同步，等待选择孩子时每 3 秒检查；从右上角余额/齿轮进入 Settings，点击 `Sync now` 会刷新余额并请求更新商品。
- 商品每 10 秒同步，失败后每 5 秒重试。已打开的商品菜单保留当时的商品快照，关掉后再次点击小狗使用新目录，以免点击过程中按钮位置发生变化。如果在首轮加载完成前打开菜单，显示加载提示；首轮目录到达后，等手指松开会自动补上商品，无需重新开关菜单。
- 目录获取失败时隐藏付费商品，仍保留免费互动，提示同步。空目录与网络失败区分处理。
- 设备通过多个 NTP 服务器同步时间后才发起 HTTPS 请求，避免证书校验因时钟未就绪失败。启动日志可区分等待时间、接口错误和商品同步成功，不输出凭据。
- 点击商品后，设备先将唯一购买请求保存到 NVS，再调用真实购买 API；服务器确认扣币后才更新余额并播放动作。喂食、喝水、陪伴动作后再开心，拒绝或失败时不播放购买成功动画。
- 服务端校验家庭归属、商品状态、显示价格和版本、余额；余额、流水、宠物喂养计数及购买记录在同一事务内更新。
- 网络超时或响应丢失时，设备保留同一个请求 ID 自动重试，重启后也继续确认；结果未确定前不会接受新的付费购买。免费操作仍可使用。
- 商品已更名、改价、变更动作或删除时，旧菜单请求会被拒绝，不会按新价格直接扣币。关闭菜单后重新打开查看最新商品。

## 上线步骤

1. 先执行之前的账号与金币迁移，再在 Supabase SQL Editor 执行 `supabase/migrations/20261116_family_shop.sql`。
2. 重新部署家长端/API，继续使用已有服务端 Supabase 配置，无需新增密钥。
3. 编译并烧录新固件。当前应用分区已扩大至 6MB；旧 3MB 设备首次升级需按 [图片压缩与6MB分区](图片压缩与6MB分区.md) 先备份并迁移数据分区，保留 NVS 与设备身份。
4. 登录家长端，确认 Water 1 credit、Food 2 credits 出现，新增一个创意商品并选择动画。
5. 等设备同步目录或从右上角进入 Settings 点击 `Sync now`，点击小狗购买，确认余额、动画、家长端消费流水一致。

迁移新建 `family_shop_items` 与 `device_shop_purchases`，对已有家庭补充两种内置商品，对以后新建的家庭通过触发器初始化。不会删除旧全局商品、余额或历史流水。新版页面和设备改用家庭目录，旧 `shop_items` 不再作为当前设备兑换来源。

数据库有明确的家庭权限隔离，家长客户端不能直接访问表。并发新增也不能超过 10 个可用商品；删除采用归档方式，历史消费记录保留。内置商品名称、动作和不可删除规则由数据库约束保证。

## 接口

- 家长：`GET/POST /api/v1/family/shop`，`PATCH/DELETE /api/v1/family/shop/:id`。
- 设备：`GET /api/v1/device/shop`，`POST /api/v1/device/shop/purchase`。
- 购买请求包括商品 ID、请求 ID、设备显示的价格和目录版本；家庭、孩子及最终扣款金额由服务端决定。
- SQL 回归：`supabase/tests/family_shop.sql`，仅用于隔离测试数据库。

## 验证与边界

修复菜单缩放残影：LVGL 8.3 缩小图片时未完整重绘旧图区域，造成大小两只狗叠加的视觉效果。应用现在在改变缩放前后明确标记图片区域重绘，保留菜单中小狗缩小的效果。回归改为部分区域刷新，先复现旧实现残留 2,460 个像素，再验证 40 帧各打开/关闭两次，共 160 次缩放与整屏重绘结果一致。

自适应菜单已重新编译并烧录。使用实际 LVGL 字体验证了 2–12 个操作的按钮均在屏幕内、互不重叠，Cookie 在全部尺寸下均能完整显示；浏览器也检查了 5 个和 12 个操作的页面。设备启动后观察 45 秒，约 5.9 秒完成校时，约 19.8 秒同步到真实接口的 3 个商品，未观察到崩溃、PNG 解码或内存分配错误。本次菜单修改无需重新部署家长端或执行 SQL。

已在隔离 PostgreSQL 中验证内置商品、10 个上限、家庭隔离、未分配设备、余额不足、旧价格、商品归档和购买幂等。并发测试验证 8 次同请求只扣一笔、8 次独立购买余额和喂养计数一致、12 次并发新增最多成功 8 次。

HTTP 测试验证登录、家庭来源、输入校验、目录和商品管理、价格版本精度及购买错误响应。家长端与固件构建通过，新固件已烧录至 `/dev/cu.usbmodem1101`。手机尺寸下以模拟接口验证新增、改价与动作选择、删除、10 个上限及删除后恢复新增。设备菜单浏览器预览可在 `apps/pet-device/preview/index.html` 查看，使用模拟目录和余额；实际设备通过真实 API 扣币。最多 12 个按钮的布局检查未发现互相重叠或超出屏幕。

图片经 TinyPNG 压缩并改为按帧选择 PNG / RGB565 后，固件约 1.92MiB；应用分区已扩大到 6MiB，剩余约 68%。压缩结果更大或一样大时保留原图，旧数据分区迁移已完成，配对信息保留。详见 [图片压缩与6MB分区](图片压缩与6MB分区.md)。真实线上购买及实机动作仍需联调，浏览器预览不能替代实机触摸验证。
